# T5838 microphone control and audio boundary

Include `<nsx/sensors/t5838.h>` and link `nsx::sensor_t5838` (option
`NSX_SENSOR_T5838`, installed component `t5838`). This is a native, portable
control driver for Acoustic Activity Detect (AAD): Analog, Digital1 and Digital2.
PDM capture, decimation, DMA and PCM buffers remain in the audio layer. The common
I2C/SPI bus is not extended with a fake microphone transaction kind.

A caller-owned context borrows a `t5838_control_t`. Its required `write_frame`
callback synchronously emits a complete THSEL waveform in units of microphone
CLK cycles; it must preserve the ongoing CLK and guarantee pulse timing, including
under interrupts. The encoder provides MSB-first device/write byte `0xa6`, register
and value; pilot/zero/one/stop durations are 10/10/30/130 CLK cycles, with 10-cycle
spaces and at least five CLK cycles before and after. Use a timer/DMA or a
qualified bounded implementation. `runtime.delay_us` only guarantees a minimum
delay and cannot provide the upper bounds needed for this wire protocol.

No board-specific THSEL emitter is claimed here. The application must supply it
for the actual pins/timer and validate waveforms on hardware. There is no identity
probe, register readback, or enable-ACK capture in this first implementation.
Transport success means the waveform was delivered, not that a microphone was
present. Optional `read_wake` samples the pin; a GPIO ISR/event queue is needed
when short pulses must be retained. Do not treat the roughly 12 us enable pulse
as acoustic activity.

Config uses typed modes/filter/algorithm choices and explicit register codes for
digital thresholds and pulse lengths. Defaults follow the datasheet examples:
Analog 70 dB SPL / 4.4 kHz; digital defaults 70 dB absolute, 45 dB floor, +3 dB
relative, both algorithms, zero minimum-duration codes. Those are typical
calibration values, not guaranteed physical trigger levels. Digital filter and
pulse timing vary with the D1 clock. The driver enforces documented ranges and
writes the rev1.2-required reserved settings for digital AAD.

## Lifecycle and shared clocks

Bind/validate/encode perform no I/O. Application owns power, fixed SELECT wiring,
shared CLK and per-microphone THSEL/WAKE. Serialize the whole microphone group,
including capture and clock handoffs; a per-THSEL lock is not sufficient.

1. Stop capture/DMA and provide a continuous programming clock between 50 and
   200 kHz (exclusive endpoints). When coming from capture, wait at least 2 ms
   in that intermediate sleep mode.
2. Init both contexts. Each unlocks and writes its config with AAD disabled.
   Enable both while the programming clock still runs.
3. For Analog/D2, wait at least 2 ms at the programming clock, then stop CLK low.
   For D1, change continuously to 400–800 kHz. A low gap of about 70 us resets D1;
   a normal stop/restart clock handoff is not sufficient.
4. For ordinary audio, configure AAD OFF and select a supported capture clock.
   Discard startup/wake transients (datasheet typical settling is 6 ms; qualify
   the required margin for the board).

The [pair example](../examples/spark/t5838_pair.c) programs both microphones
before one shared transition and invalidates both caches if any stage fails.
It needs separate THSEL endpoints; tied control lines require a board-specific
broadcast policy. It does not instantiate GPIOs, PDM capture, or timers.

A power cycle resets AAD. Clock-off also resets registers when Analog/D2 are not
enabled. External register writes also invalidate the cached configuration.
Call `t5838_invalidate` on every affected context; restore programming
CLK and fully init before enabling again. `disable` requires programming CLK and
invalidates the cached config. Any write failure makes the physical state
uncertain: recover the whole group. `validate_operating_clock` checks final mode
combinations; it neither changes clocks nor proves a safe transition occurred.

## NSX capture

The existing `nsx-audio` API supports stereo PCM16 with caller-owned buffers.
Use `num_channels=2` and `NSX_AUDIO_PDM_CLK_750KHZ` for T5838 low-power capture.
Do not select `NSX_AUDIO_PDM_CLK_1_5MHZ`: it lies outside this microphone's capture
ranges. High-quality mode requires 2.0–3.7 MHz; exposing such a clock through
`nsx-audio`, plus a qualified THSEL/programming-clock handoff, remains integration
work rather than a change to this sensor module's bus API. The SDK interface was
checked at `1f18f01555897ed8e06437ff9727f2bb61771e70`.

SELECT is sampled at power-up: one microphone tied low, the other high for stereo.
Do not change it dynamically. Board wiring determines which physical microphone
maps to each PCM channel; confirm with a single-microphone stimulus. Keep the
capture context and aligned DMA/PCM buffers alive through stop, and defer heavy
processing from ISR callbacks. See [Spark integration notes](../examples/spark/README.md).

Source: TDK **DS-000383 rev1.2 (2025-09-04)**, sections 5.3–5.7 and 6–7,
[manufacturer document mirrored by Farnell](https://www.farnell.com/datasheets/4761948.pdf).
Earlier revisions differ in digital AAD reserved writes and examples; this
implementation follows rev1.2. No vendor implementation is copied. Tests verify
encoding, configuration, recovery and two independent devices; they do not
qualify electrical timing, stereo capture or acoustic performance on Spark.
