# MPU6050 portable API migration (unreleased)

See [pre-v1 API cleanup](api-cleanup.md) for public naming/type changes and the
shared lifecycle comparison.

Link `nsx::sensor_mpu6050` and include `<nsx/sensors/mpu6050.h>`. The driver uses
common I2C bus, runtime and status types. NSX applications additionally link
`nsx::sensor_port_nsx` and include `<nsx/sensors/port_nsx.h>`. Plain CMake and
FreeRTOS applications supply synchronous HAL callbacks; Zephyr wrappers remain
future work. No vendor tree, heap allocation, or global device state is required.
This is a breaking, unreleased migration; version metadata remains v0.3.0.

## API changes

| Previous API | Portable replacement |
| --- | --- |
| `nsx_mpu6050.h`, `nsx::sensors` | `<nsx/sensors/mpu6050.h>`, `nsx::sensor_mpu6050` |
| Context stores NSX I2C/address | Endpoint owns address; context copies bus/runtime descriptors |
| Combined binding/setup `mpu6050_init` | `bind(ctx, bus, runtime)`, `probe(ctx, &id)`, then `init(ctx, &config)` |
| `mpu6050_test_connection` | `mpu6050_probe`; read-only identity check |
| Config `sample_rate` and `sleep_cfg` | Exact divider; init always ends asleep. Explicitly wake afterwards |
| Integer return codes / direct scalar returns | `nsx_sensor_status_t`; scalar getters/converters take output pointers |
| Raw `read_sensors` without capacity | `read_sensors(ctx, bytes, capacity)` (at least 14), or typed `read_raw` / `read_sample` |
| FIFO word access | Corrected `fifo_pop`; also typed `read_fifo` and capacity-aware `read_fifo_bytes` |
| Unbounded reset / mean / calibration | Reset and averaging take timeout; calibration takes samples, iteration limit, deadzones and timeout |
| Implicit calibration during setup | Explicit `mpu6050_calibrate`; no calibration during init |

Function names above omit the `mpu6050_` prefix where space is limited. Existing
range, filter, clock and interrupt enums/config fields are retained. Private
register definitions live in C. Direct register-setting functions remain
available; common convenience functions compose them.

## NSX example

```c
#include <nsx/sensors/mpu6050.h>
#include <nsx/sensors/port_nsx.h>

static nsx_sensor_nsx_context_t endpoint;
static mpu6050_context_t motion;

/* App supplies delay_us (wait at least the requested duration); now_us is optional.
 * Runtime user storage, I2C configuration and any lock hooks must outlive motion. */
nsx_sensor_status_t motion_start(nsx_i2c_config_t *i2c,
                                const nsx_sensor_runtime_t *runtime)
{
    nsx_sensor_status_t s = nsx_sensor_nsx_bind_i2c(
        &endpoint, i2c, MPU6050_I2C_ADDRESS_AD0_LOW, NULL);
    if (s == NSX_SENSOR_OK) s = mpu6050_bind(&motion, &endpoint.bus, runtime);
    mpu6050_config_t config = mpu6050_default_config();
    if (s == NSX_SENSOR_OK) s = mpu6050_init(&motion, &config);
    if (s == NSX_SENSOR_OK) s = mpu6050_set_sleep(&motion, 0);
    return s;
}
```

Serialize complete driver operations per device. The example omits transport lock
hooks for an application that already serializes bus access; shared buses can use
the adapter's lock hooks. Genuine repeated-START reads require the SDK revision
specified in [the NSX port guide](../nsx-port.md).

`bind` is pure and requires I2C, TX capacity >=3 and RX capacity >=14. Probe needs
no runtime. WHO_AM_I bits 6:1 identify MPU6050 independently of address 0x68/0x69;
this is not support for the different MPU6500 family.

`init` validates settings, probes, resets with a 200 ms budget, configures the
ranges/filter/divider, disables FIFO/interrupts, and leaves the part asleep.
Defaults are X-gyro PLL, DLPF 44/42 Hz, +/-2g, +/-250 dps, divider 9 (100 Hz).
A failed configuration write can have changed hardware; it invalidates the
context until successful init. Read errors preserve output values. Configuration
caches describe successfully applied settings; do not modify hardware outside
the driver or write the context's private fields.

Clock changes and wake-up need device settling before measurements are useful;
`set_sleep` is a direct register operation, not a wait for stable data. Use DRDY
and board-specific settling requirements. Low-power mode explicitly starts accel
cycling using the internal clock, requires FIFO disabled, and marks gyro/temp
invalid. Restore normal mode with init, then wake.

## Samples and rates

`read_raw` reads all 14 output bytes in one coherent burst; it does not wait for
fresh data. Values are signed sensor codes. `read_sample` supplies acceleration
in g, angular velocity in degrees/second, and temperature in Celsius. The validity
mask excludes disabled channels and absent values are zero. Conversion helpers
also work without a bound device and reject invalid enum values.

Acceleration sensitivities are 16384/8192/4096/2048 LSB/g; gyro sensitivities are
131/65.5/32.8/16.4 LSB/(degree/second). Temperature is raw/340 + 36.53 Celsius.
Full-scale fields occupy bits 4:3, correcting the old bit shift.

The normal sample clock is 8 kHz with DLPF disabled (0), otherwise 1 kHz. Rate is
clock/(divider+1). `set_sample_rate` accepts exact integer Hz only and rejects
unrepresentable values rather than clamping. `get_sample_rate` reads the divider
and DLPF back; low-power mode returns `E_STATE` because its wake rate is separate. The accelerometer updates at 1 kHz, so faster output rates repeat
accel data. Low-power cycling uses its separate wake-frequency setting.

## FIFO and recovery

Configure channels, wake if needed, reset FIFO, then explicitly enable FIFO.
`configure_fifo` and `reset_fifo` leave it disabled. Native frames contain enabled
channels in register order: accel XYZ, temperature, gyro X/Y/Z. Typed reads reject
auxiliary slave channels because their configured lengths are unknown; raw reads
retain support for externally configured auxiliary sources.

FIFO must be enabled for all typed, byte, and word reads: USER_CTRL.FIFO_EN
disables hardware reads as well as writes. Disabling preserves queued data;
re-enable before consuming it.

Both readers snapshot the available byte count (maximum 1024) and honor caller
capacity. Typed reads batch complete frames into bursts of up to 14 bytes,
checking overflow before and after each burst. A failed burst publishes none of
its frames, even if hardware consumed bytes. Batching reduces bus overhead for
small frames; achievable rates still depend on bus speed, scheduling and capacity. Typed reads consume only complete frames, leaving an incomplete tail.
Empty/no complete data returns `NSX_SENSOR_AGAIN`. `completed` reports only
successfully published frames or bytes. No timestamp is invented for FIFO data.

Overflow, failed FIFO consumption, or a failed read-to-clear interrupt status
requires explicit `reset_fifo`, then re-enable. An unsuccessful transfer can have
consumed bytes even though no sample was published. A failed reset leaves FIFO
unusable; retry reset or reinitialize if configuration was invalidated. Range,
rate, clock, power, offset, or format changes also require a FIFO reset. Mixing raw
or word reads with typed frames loses known alignment; reset before typed reads.
Previously published frames remain usable after a later batch failure.

Public interrupt status reads consume flags and remember observed FIFO overflow.
Any-read interrupt clearing (`rdClear=1`) is rejected while FIFO is configured or
enabled, preventing unrelated reads from erasing overflow evidence. External
register access can bypass this protection and is outside the driver contract.

## Timing and calibration

Delay callbacks must wait at least the requested time. Optional `now_us` must be
monotonic. Timeouts include requested waits and, when a clock is supplied, elapsed
time checked between transfers. A requested-delay budget and finite loops also
bound operations if the clock stalls. No synchronous driver can preempt a hung
HAL call: the transport must have its own finite timeout. Without `now_us`, the
timeout bounds requested delays, not bus time or scheduler oversleep.

Reset includes 100 ms settling followed by bounded reset-bit polling. FIFO reset
has a 100 ms poll budget; signal reset has a 200 ms budget including settling.
Averaging discards stale DRDY before every sample wait, waits for fresh DRDY,
then reads a coherent burst. Clearing each iteration prevents counting a sample
twice when a conversion occurred between the previous status check and burst.
This can skip conversions; it does not promise every consecutive sample.
Samples range from 1 to 4096. FIFO and low-power mode must be disabled.

Calibration is opt-in: keep the board stationary, level and +Z-up, use +/-2g,
+/-250 dps and an enabled DLPF. Defaults are 32 samples/iteration, 20 iterations,
5 seconds total, and raw deadzones 8 accel / 4 gyro. Convergence and timing depend
on sample rate and physical conditions; stillness cannot be verified by this API.
Z's expected +1g is preserved. Accelerometer offset bit 0 (factory temperature
compensation) is retained; signed offset getters mask that bit. The adjustment
uses existing MPU6050 offset-register units, not physical units.

A calibration failure leaves its result output unchanged but can leave previously
written offsets applied. Save/restore offsets explicitly or reset/reinitialize;
there is no automatic rollback. Reset can discard user offsets. Max iterations
is 256; offset arithmetic rejects overflow instead of wrapping.

## Validation and remaining hardware work

The portable CTest suite covers lifecycle/idle init, register masks and rates,
signed samples/scales, all 31 native FIFO formats, partial reads, overflow,
ambiguous consumption, timeout paths, compensation-bit preservation, calibration
convergence in a simulated sensor, and injected transfer failures. The build
matrix exercises independent driver selection, nested and relocated installed
C/C++ consumers, and ASan/UBSan. NSX adapter tests exercise probe at address 0x69.

These are software checks. Real-device wake/reset settling, fresh-data behavior,
FIFO rollover/overflow, interrupts, low-power mode, and calibration convergence
still need hardware qualification. Neither SPI support nor a self-test procedure
is added; MPU6050 is I2C-only. Command queues remain a separate transport follow-up.
