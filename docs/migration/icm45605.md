# ICM-45605: portable basic SPI migration

Include `<nsx/sensors/icm45605.h>` and link `nsx::sensor_icm45605`.
The old `nsx_icm45605.h` and singleton API are removed. Version metadata remains
0.3.0 during this unreleased source-breaking transition; existing applications
stay pinned until deliberately migrated.

## Scope and ownership

This slice supports 4-wire SPI, both sensors in low-noise mode at a shared
12.5–6400 Hz requested rate, native ranges and filters, register samples,
data-ready status, opt-in INT2 pulses, and explicit stationary +Z calibration.
No FIFO, APEX, compressed packets, self-test, I2C or I3C API is exposed.
[Issue #23](https://github.com/AmbiqAI/nsx-sensors/issues/23) tracks expansion.
Spark pin/board integration and hardware validation remain in #13 and #4.

Each caller-owned context contains typed TDK device state. The transport carries
its user pointer through direct and indirect register accesses and delays. No
heap or global device binding is used. Do not copy or move the context after
binding: its callbacks refer to its address. Endpoint backing objects and runtime
callbacks must also outlive it. Serialize complete device operations, including
indirect-register sequences, and coordinate shared bus ownership in the application.

The public header includes TDK implementation types for allocation without a
heap. CMake supplies their include path; installed copies are under
`include/nsx/sensors/detail/tdk-icm45605`. Applications must not call the vendor
API directly or mutate implementation fields. This is a source API, not a
serialized or binary-stable context format. TDK headers/source retain their
original license; see PROVENANCE.md and NOTICE.

## Example

The application initializes the SPI controller, GPIO/CS, and timing hooks.
Configure mode 0 or 3, at most 24 MHz, with the datasheet's CS timing. The endpoint
must support a 4-byte write and a 14-byte read after a 1-byte command under one
CS assertion. No device I/O occurs during bind.

```c
#include <nsx/sensors/icm45605.h>
#include <nsx/sensors/port_nsx.h> /* Only for an NSX application. */

/* Keep these objects alive and do not move them after binding. */
static nsx_sensor_nsx_context_t endpoint;
static icm45605_context_t imu;

nsx_sensor_status_t initialize_imu(nsx_spi_config_t *spi, uint32_t chip_select,
                                 const nsx_sensor_runtime_t *runtime)
{
    nsx_sensor_status_t s = nsx_sensor_nsx_bind_spi(&endpoint, spi, chip_select, NULL);
    if (s != NSX_SENSOR_OK) return s;
    s = icm45605_bind(&imu, &endpoint.bus, runtime);
    if (s != NSX_SENSOR_OK) return s;
    icm45605_config_t config = icm45605_default_config();
    config.drdy_interrupt = true; /* Caller wires INT2 and schedules a worker. */
    s = icm45605_init(&imu, &config); /* Reset/configure, idle; no calibration. */
    if (s != NSX_SENSOR_OK) return s;
    return icm45605_start(&imu);
}
```

Link `nsx::sensor_port_nsx` as well for this example. Plain CMake/FreeRTOS callers
supply their own synchronous `nsx_sensor_bus_t` callbacks; no RTOS is required.
The example omits locking because the caller must serialize all access; provide
shared-adapter lock hooks if other tasks use the controller.

Defaults are ±4 g, ±500 dps, 100 Hz and ODR/4 filters, with external DRDY disabled.
Init needs `delay_us`, waits for register access, verifies identity, resets and
configures without starting acquisition. Start waits the retained TDK 70 ms
gyroscope startup bound plus an 80 ms slowest-rate period. This is a conservative
startup wait, not proof that every configured filter has fully settled.
Stop turns both sensors off. Configure and range/rate/filter setters require idle;
DRDY routing can be toggled explicitly. GPIO ownership stays with the application.

## Samples, status and calibration

`read_raw` returns signed 16-bit accelerometer, gyroscope and temperature codes.
`read` returns g, degrees/second and degrees Celsius, subtracting software axis
biases. Raw/scaled types are distinct. The direct UI path supports ±2/4/8/16 g
and ±15.625 through ±2000 dps; 32 g and 4000 dps are not valid settings here.

Reads return the latest register snapshot. They can repeat samples or skip
conversions; there is no FIFO or lossless streaming claim. An ISR only schedules
work. In a worker, `read_data_ready` consumes INT1 reset status and INT2 DRDY
status. It requires `drdy_interrupt=true`: the hardware mask gates the status
flag as well as the pin. Polling that flag still enables active-high push-pull
INT2 pulses (the GPIO need not be connected to an ISR). When disabled, direct
register snapshots remain available; data-ready polling returns `E_STATE`. An observed RESET_DONE after init invalidates the
configuration. Consuming-status read failure also requires init because reset
evidence may have been lost. Other sample-read failures preserve output.

`calibrate(ctx, samples, timeout_us)` is explicit, blocking and bounded, accepts
1–4096 samples, and requires DRDY enabled and the running device stationary and level with
+Z measuring +1 g. It discards old DRDY before each observation and waits for a
new event; it averages uncorrected samples, so recalibration does not subtract
previous biases. Biases update only on complete success; no sample/bias partial
publication occurs. This is offset estimation, not a motion-quality check or
factory calibration. `set_bias` applies finite externally measured values; zero
bias clears compensation. Init clears biases.

With `now_us`, calibration also checks elapsed time. Without it, only requested
waits are bounded; bus callbacks must provide their own completion bounds. A
frozen clock cannot cause an infinite poll because the requested-wait budget is
also tracked. Conversion events may be skipped under heavy host latency.

Mutation errors invalidate initialization: call init rather than assuming a
partial configuration was rolled back. The wrapper latches the first transport
error, initializes direct/indirect read buffers for vendor safety, and suppresses later I/O in
that operation. It preserves the shared status (including timeout/busy) rather
than collapsing every bus failure into a device error.

## Build and evidence

`NSX_SENSOR_ICM45605` selects this core. All six cores are now portable;
`nsx::sensors` aggregates the selected cores and is installed in the portable
export. `NSX_SENSORS_LEGACY_NSX` is removed. NSX endpoints use the separate adapter.
No registry repin or v1 release occurs here.

Host tests exercise separate devices and delay users, indirect addresses,
reserved-bit preservation, both data byte orders, all native range conversions,
first-error propagation, partial transfers, reset failure, idle/running guards,
consuming interrupt status, and repeated/frozen-clock calibration. CMake tests
cover standalone selection, nested and relocated installed C/C++ consumers;
NSX adapter tests execute a real SPI identity probe. The vendor's little-endian
register bitfield layout is retained; tested Arm/host toolchains are the scope,
not an assertion of portability to every C bitfield ABI.

Source reference: TDK DS-000576 Rev 1.0 (registers, conversion factors, modes and
interfaces), available from the [manufacturer](https://invensense.tdk.com/wp-content/uploads/documentation/DS-000576_ICM-45605.pdf)
and [distributor mirror](https://www.farnell.com/datasheets/4420394.pdf), and the
pinned TDK eMD 2.1.0 basic subset described in PROVENANCE.md.
Hardware is unavailable. Electrical timing, physical rates, startup/filter
settling, interrupt behavior, calibration quality and Spark wiring remain
unqualified; host tests establish software behavior only.
