# MAX86150 portable migration and driver audit (unreleased)

See [pre-v1 API cleanup](api-cleanup.md) for public naming/type changes and the
shared lifecycle comparison.

Include `<nsx/sensors/max86150.h>` and link `nsx::sensor_max86150`. NSX applications
also use `<nsx/sensors/port_nsx.h>` / `nsx::sensor_port_nsx`. The portable core
supports plain CMake and caller-supplied bare-metal or FreeRTOS HAL callbacks.
Zephyr wrappers remain separate work. Metadata stays at 0.3.0 during this
unreleased transition; the previous API is intentionally not source compatible.

## Lifecycle and configuration

`max86150_bind(ctx, bus, runtime)` is pure. It copies descriptors for an I2C
endpoint (7-bit address 0x5e), TX limit at least 3 and RX limit at least 12.
`probe(ctx, &id)` reads PART_ID, accepting 0x1e, without changing hardware.
`validate_config` is pure. Init validates, probes, resets with a 100 ms timeout,
configures, disables interrupts/FIFO, and finishes in shutdown.

```c
#include <nsx/sensors/max86150.h>
#include <nsx/sensors/port_nsx.h>

static nsx_sensor_nsx_context_t endpoint;
static max86150_context_t optical;

nsx_sensor_status_t optical_start(nsx_i2c_config_t *i2c,
                                  const nsx_sensor_runtime_t *runtime)
{
    nsx_sensor_status_t s = nsx_sensor_nsx_bind_i2c(
        &endpoint, i2c, MAX86150_I2C_ADDRESS, NULL);
    if (s == NSX_SENSOR_OK) s = max86150_bind(&optical, &endpoint.bus, runtime);
    max86150_config_t config = max86150_default_config();
    config.led_amplitude[0] = 40; /* Nominal 8 mA at default range; application choice. */
    config.led_amplitude[1] = 40;
    if (s == NSX_SENSOR_OK) s = max86150_init(&optical, &config);
    if (s == NSX_SENSOR_OK) s = max86150_start(&optical);
    return s;
}
```

Caller-owned bus/runtime storage must outlive the device. Serialize complete
operations on each device and provide bus locking when multiple devices share
an endpoint. HAL transfers must have finite timeouts; they cannot be preempted.
Delay callbacks must wait at least the requested duration. Optional monotonic
`now_us` adds elapsed-time checks; otherwise timeout bounds requested waits.
Reset also has a finite delay budget if the supplied clock stalls.

Defaults select IR, red, ECG, Off; PPG 400 sps with 100 us pulses/no averaging;
ECG 400 sps, PGA 1 and IA 20; non-rollover FIFO with 15 free-space threshold.
LED amplitudes default to zero: choose currents explicitly for your board.
PPG rates may be adjusted by hardware for pulse-width/LED count limitations or
ECG synchronization, and averaging decimates output. Read `get_ppg_config`
for register readback; requested config is not an effective sampling-rate promise.

`configure` and direct settings require shutdown/FIFO disabled and invalidate
prior FIFO data interpretation. Use `configure` to replace all settings; direct setters validate and update
only their corresponding register fields. `start` flushes
old data and enables FIFO/acquisition. `powerup` only exits shutdown, while
`set_fifo_enable(1)` starts a new FIFO epoch on its rising edge, discarding old
queued frames. Repeating an already-enabled request is a no-op.

Shutdown first freezes FIFO pushes and preserves full-state interrupt evidence.
It allows 100 ms (one slowest PPG period) for any active conversion to finish
before returning. Clear/recovery ends shutdown with FIFO disabled and uses its
hardware flush edge, not writes to the read-only overflow counter. Device settling
and that conservative shutdown interval still require real-hardware validation.

## FIFO APIs and loss semantics

`max86150_frame_t` carries slot identities, count, and four `int32_t` raw values:
PPG is unsigned 19-bit, ECG is signed 18-bit two's complement. Unused entries are
zero. These are sensor codes, not calibrated physiological measurements. Slots
must be contiguous, unique data sources, with PPG preceding the single ECG slot.
Off entries terminate the list. All-Off is valid for idle configuration but
cannot start acquisition. Reserved slot encodings and LED ranges are rejected.

Both readers honor frame capacity and use whole-frame bursts up to 96 bytes,
further limited by the endpoint's RX capacity. Outputs are published only after
a successful burst. `completed` reports previously published frames if a later
burst fails. Empty returns `AGAIN`; any ambiguous FIFO consumption invalidates
FIFO state until explicit clear/start. Configuration-write failures and failed
consuming interrupt-status reads require init instead.

- **Continuous `read_fifo`** requires awake, FIFO enabled, rollover off,
  repeating A_FULL and no A_FULL clear-on-data (the defaults). The latter two
  preserve full-state evidence across successive drains.
  Production continues during draining. Observed overflow returns `E_OVERFLOW`;
  queued old frames are protected by non-rollover behavior. Hardware clears OVF
  every time a complete frame is popped, so overflow that occurs during a burst
  may disappear before software can observe it. Success does not promise a
  gapless sequence. Service the FIFO with sufficient bus bandwidth and latency.
- **`read_fifo_snapshot`** first disables FIFO pushes, then snapshots status and
  pointers before popping any frame. Overflow is therefore checked while stable.
  FIFO remains disabled; subsequent calls drain remaining queued frames without
  restarting production. Explicit start begins a new capture and discards any
  unread frames. This API intentionally has capture gaps. Rollover configurations
  can be inspected through this API, but an observed overflow requires recovery.

Continuous reads retain one queued frame, adding one frame of latency; `AGAIN`
means fewer than two frames are queued. Use `read_fifo_snapshot` to drain the
final frame. Keeping the queue nonempty makes equal pointers unambiguously full
once consumption starts, even when a producer reasserts A_FULL between status
and pointer reads. A failed pre-burst overflow check invalidates FIFO state and
requires explicit recovery, including when no frames were consumed.

Equal read/write pointers alone cannot distinguish empty from exactly full.
The driver retains read-to-clear A_FULL evidence across public status reads and
uses it with the frozen/snapshotted pointers. Known snapshot counts are decremented
as data is published. Do not access registers externally or modify private
context fields: this breaks the evidence and alignment tracking.

`get_interrupts` consumes both interrupt registers. `get_int1` and `get_int2`
are compatibility conveniences that also consume both, while retaining A_FULL
internally. A failed consuming status read invalidates both FIFO evidence and
configuration: it may have erased PWR_RDY after a power reset, so clear/start
cannot safely reuse cached settings. Call init before acquiring again. Observed
unexpected PWR_RDY also invalidates configuration, including during FIFO
recovery. Init consumes an existing boot flag before reset/configuration, then
checks for pending power-reset evidence before reporting success. These checks
cannot detect every power interruption: shutdown clears interrupts, so a flag
cleared before a checked read is not observable. Interrupt-enable masks are
0xe0 and 0x84; the proximity-enable bit is intentionally excluded. Automatic
proximity transitions flush FIFO and always roll over, so that mode is unsupported
in this first portable contract. Pilot-current slots and threshold configuration
are retained, but do not turn automatic proximity mode on.

## Audit corrections and migration map

| Legacy behavior/API | Portable correction/replacement |
| --- | --- |
| `init(ctx, nsx_i2c, address)` only binds | Separate bind/probe/init/start; idle init and common statuses |
| Getter values and `void` setters hide I/O failures | Status plus output arguments; distinguish valid zero from errors |
| Empty pointer pair 0/0 computes 32 samples; equal nonzero also treated full | Full-state evidence plus pointers, with explicit empty result |
| FIFO size/slot list supplied independently by caller | Validated context-owned slots and frame capacity; no fixed-buffer overrun |
| Masks ECG to an unsigned value; host-endian reconstruction | Explicit big-endian decoding and signed 18-bit ECG extension |
| `set_fifo_overflow_counter` writes a read-only register | Removed; hardware flush provides recovery |
| `clear_fifo` writes three pointer/counter registers without checking | Explicit stop/flush recovery with every error propagated |
| LED selector silently falls back to LED1 | Reject invalid selectors; LED range 2/3 is reserved |
| LED amplitude described as 7-bit | Full 8-bit amplitude, validated by tests |
| PPG full-scale comment starts at 16384 nA | Datasheet starts at 4096 nA, with 7.8125 pA/LSB |
| Header declares `set_data_rdy_int_flag`, implementation defines a different name | Unified `set_interrupts` bit masks |
| Generic unchecked register/pointer writes | Removed from public API to protect cached config and FIFO evidence |
| Unbounded/non-waiting reset | Bounded reset with runtime hooks and invalid state until init |

The original direct PPG/ECG/gain/current/slot configuration names largely remain,
with common status returns. Individual interrupt setter helpers are replaced by
`set_interrupts`. FIFO pointer/overflow getters are grouped into `get_fifo_state`;
`get_part_id` is replaced by probe. Old `read_fifo_samples` is replaced by typed,
capacity-aware continuous or snapshot reads. There is no unsafe compatibility shim.

## Evidence and pending checks

The audit uses Maxim Integrated MAX86150 datasheet 19-8402 Rev 2 (12/18):
[manufacturer PDF](https://www.analog.com/media/en/technical-documentation/data-sheets/MAX86150.pdf).
Key sections are registers 0x04–0x0f, PPG/ECG configuration tables, and FIFO
Description/Handling/Flush. The implementation remains native Ambiq code.

Host tests cover empty and exactly-full queues at zero/nonzero pointers, wrap,
public status consumption, signed extrema, valid slot permutations, capacities,
bus limits, partial failure, overflow, reset timeout, invalid inputs, reserved-bit
preservation, configuration failures and separate contexts. CMake tests cover
individual selection and nested/relocated C/C++ consumers; NSX tests probe via
the shared repeated-START adapter.

Hardware is unavailable. Actual slot timing, FIFO freeze/full evidence, interrupt
behavior, reset/shutdown settling, ECG/PPG synchronization, electrode/optical
signal quality and sustainable acquisition rates remain unqualified. These tests
establish software contracts, not physical sensor accuracy or lossless streaming.
