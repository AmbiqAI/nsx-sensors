# INA228 portable API migration (unreleased)

See [pre-v1 API cleanup](api-cleanup.md) for public naming/type changes and the
shared lifecycle comparison.

INA228 is now a portable C driver using the common sensor bus/status API.
Link `nsx::sensor_ina228` and include `<nsx/sensors/ina228.h>`. NSX applications
also link `nsx::sensor_port_nsx` and bind the shared adapter as described in
[the NSX port guide](../nsx-port.md). This is a breaking API change on the path
to v1; existing applications retain their immutable v0 dependency pins.

| Previous API | Portable API |
| --- | --- |
| `#include "nsx_ina228.h"` | `#include <nsx/sensors/ina228.h>` |
| Binding-only `ina228_init(ctx, i2c, address)` | `ina228_bind(ctx, bus)`; no I/O |
| `ina228_validate(ctx)` | `ina228_probe(ctx, &identity)`; identity reads only |
| Individual setup calls after binding | `ina228_init(ctx, &config)`; direct setters remain available |
| Numeric transport results | `nsx_sensor_status_t`; shared adapter retains SDK diagnostics |
| Failed reads could zero/overwrite outputs | All failed reads preserve caller outputs |
| Uncalibrated scaled reads returned numbers | Return `NSX_SENSOR_E_STATE` until calibration succeeds |

## Initialization

The application must provide its shunt resistance and maximum expected current.
The default configuration deliberately leaves those two values zero, so it is
invalid until they are set. Initialization leaves the ADC in shutdown. Timing
defaults match ADC power-on settings: 1052 us per conversion, one-sample
averaging, wide shunt range, transparent active-low alerts.

```c
#include <nsx/sensors/ina228.h>
#include <nsx/sensors/port_nsx.h>

static nsx_sensor_nsx_context_t endpoint;
static ina228_context_t monitor;

nsx_sensor_status_t start_monitor(nsx_i2c_config_t *initialized_i2c)
{
    /* Application guarantees exclusive IOM access; otherwise supply lock hooks. */
    nsx_sensor_status_t status = nsx_sensor_nsx_bind_i2c(
        &endpoint, initialized_i2c, 0x40, NULL);
    if (status == NSX_SENSOR_OK) status = ina228_bind(&monitor, &endpoint.bus);
    ina228_config_t config = ina228_default_config();
    config.shunt_ohms = 0.1f;
    config.max_current_amps = 0.5f;
    if (status == NSX_SENSOR_OK) status = ina228_init(&monitor, &config);
    /* Init leaves the ADC idle; explicitly start acquisition when ready. */
    if (status == NSX_SENSOR_OK)
        status = ina228_set_mode(&monitor, INA228_MODE_CONTINUOUS);
    return status;
}
```

`ina228_validate_config` is pure. It checks enum bounds, finite positive physical
inputs, and a representable nonzero SHUNT_CAL. The application still chooses a
shunt/current combination within the part's physical voltage and power limits.
`probe` checks manufacturer and revision-independent die identity and returns
both raw identity registers without changing configuration.

`init` validates and probes, stops conversions, programs the selected range,
verifies calibration by reading it back, clears accumulators, sets alert
latch/polarity, and leaves the ADC in shutdown. `ina228_set_mode` explicitly
starts continuous or triggered conversions; sampling mode is not an init option. It disables conversion delay,
shunt temperature compensation, conversion-ready alert output, and slow-alert
comparison; existing threshold registers are left unchanged. It does not issue
a device reset or wait for a new conversion. Invalid configuration causes no
I/O; failed initialization I/O invalidates calibration and may leave partial
hardware configuration. Retry `init` to restore the explicit configuration.

## Direct operations, units, and failure recovery

Direct register APIs work after `bind`. Reads of voltage, temperature, raw
accumulators, and diagnostics do not require calibration. Scaled current,
power, energy, and charge require verified calibration from `init` or
`set_shunt`. Units remain mA, mV, mW, degrees Celsius, joules, and coulombs.
Raw energy is unsigned 40-bit in `uint64_t`; raw charge is signed 40-bit in
`int64_t`. Use the raw APIs for exact accumulator deltas; float results cannot
retain all 40 bits. Scaling overflow returns `E_OVERFLOW` without publishing.

`set_shunt` preserves cached calibration if validation or its initial range
read fails before any write. Once a calibration write is attempted, a failure
or readback mismatch disables scaled reads. `set_adc_range` preflights the new
calibration before changing hardware; an impossible range switch performs no
I/O. An attempted range/calibration write failure invalidates the cache.
Reinitialize or successfully set the shunt again before scaled reads.

`reset` invalidates calibration before sending the reset command, including
when transport reports failure. It does not wait for a fresh measurement.
Changing shunt scaling does not automatically reset accumulated history; stop
conversions and reset accumulators when starting a new measurement window or
changing scaling. Complete conversions before trusting newly configured values.
No getter waits for freshness or promises an atomic multi-register snapshot.

Reads of DIAG_ALRT may clear latched flags; alert getters and read/modify/write
setters have that same hardware side effect. Reading ENERGY/CHARGE clears the
respective overflow flag. Resetting the accumulators does not clear those two
flags. Do not automatically retry failed destructive reads: the device may
have consumed or cleared data even though no result was published.

Serialize complete operations per physical device, separately from the shared
adapter's IOM lock. The driver performs one combined command/read transaction
per register read and one three-byte transaction per register write. It requires
an I2C endpoint with TX capacity at least 3 and RX capacity at least 5 bytes.
Two contexts can use independent endpoints without shared device state.

## Verification and provenance

The implementation retains the existing Ambiq-authored INA228 port and its
v0.3 arithmetic regression cases, updated for the new API/error contract.
Register behavior was checked against TI's [INA228 datasheet, SLYS021A](https://www.ti.com/lit/ds/symlink/ina228.pdf),
particularly CONFIG, DIAG_ALRT, and the measurement registers.

`tests/ina228_host_unit.sh` and the portable CTest suite cover calibration,
20-/40-bit decoding, exact raw deltas, lifecycle, all initialization I/O failure
positions, output preservation, side-effect registers, and two instances.
`tests/portable_build.sh` also checks sanitizers, independent driver selection,
and relocated C/C++ package consumers. NSX adapter tests exercise INA228 probe
through the actual adapter. Real SDK header compilation covers eight SoCs.
Physical accuracy, timing, repeated-START waveforms, and hardware recovery are
still unqualified; no v1 release or registry pin is changed here.
