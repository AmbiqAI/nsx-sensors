# ICM-42670-P basic driver

Include `<nsx/sensors/icm42670.h>` and link `nsx::sensor_icm42670`.
The root CMake option is `NSX_SENSOR_ICM42670`; the installed component is
`icm42670`. Zephyr selects `CONFIG_NSX_SENSOR_ICM42670` and uses the same core
through the shared bus endpoint; a Zephyr sensor API wrapper is not supplied.

Bind a zero-initialized caller-owned context to an I2C or 4-wire SPI endpoint
and a runtime with `delay_us`. The bus needs TX >= 2 and RX >= 14. I2C uses
0x68/0x69 at <= 1 MHz; SPI uses mode 0/3 at <= 24 MHz with datasheet CS timing.
The endpoint owns address/CS. Callers serialize whole operations and exclusively
own sensor configuration. No GPIO, IRQ handler or scheduler is owned by the core.

`icm42670_default_config()` selects ±4 g, ±500 degrees/s, 100 Hz for both
sensors and 53 Hz filters, with INT1 routing disabled. `init` probes identity
0x67, resets, configures and finishes stopped. `configure` and the direct
range/rate/filter/interrupt setters require stopped state. `start` enables both
sensors in low-noise mode; `stop` disables both. Supported rates are 12.5, 25,
50, 100, 200, 400, 800 and 1600 Hz. ICM-42670-S is not accepted.

Timing is deliberately conservative: reset waits 60 ms before writing reset
(to recover safely from an uncertain prior start), then 1 ms for reset settling.
Start waits 60 ms and stop waits 21 ms, including transfers reporting failure.
These cover the 200 us write quiet time, 45 ms minimum gyro on-time and >20 ms
gyro off-to-on interval. They are blocking runtime delays, with the shared bus
released. The endpoint must bound individual bus calls. These delays are not a
sample-freshness guarantee, especially at 12.5 Hz.

`read_raw` returns one 14-byte temperature/accel/gyro register snapshot.
`read` reports g, degrees/s and degrees C (temperature = raw/128 + 25).
`read_data_ready` consumes read-to-clear DRDY status and works without GPIO
routing. Optional routing is INT1, active-high push-pull, default 100 us pulse.
Call from a worker, not an ISR. Samples can repeat or be skipped; this is not a
FIFO acquisition API. Reset leaves the context uninitialized; call init again.

Bad arguments and state errors cause no I/O. Read errors preserve caller
outputs, although failed status reads can consume the flag. Mutation failures
may have partly changed hardware and require init before further acquisition.
An unexpected external reset/power loss is outside exclusive ownership: the
application must reinitialize after a known supply interruption.

The implementation uses only bank-0 registers. FIFO, APEX, self-test, calibration,
low-power operation and I3C are not included. See [provenance](../PROVENANCE.md)
for the datasheet and reference-derived shared-SPI workaround. Host models test
protocol/state behavior; they do not establish physical timing, filter response,
noise or measurement accuracy. **Hardware qualification is pending.**
