# BME688 forced-mode measurements

The native BME688 driver supports compensated temperature (C), pressure (Pa),
humidity (%RH), and optional raw gas resistance (ohms). It identifies chip ID
`0x61` and BME688 high-gas variant ID `1`. BME680 and early engineering samples
with another variant ID are rejected. Hardware operation has not been qualified.

This is the forced-mode milestone for issue #14. Parallel mode, multi-step
heater-profile scanning, command queues, and BSEC are follow-up work. Raw gas
resistance does not provide IAQ, VOC concentration, gas identification, or a
BSEC output. The driver does not interpret resistance as an air-quality score.

## Bring-up and ownership

Include `<nsx/sensors/bme688.h>` and link `nsx::sensor_bme688`. The application
supplies a shared `nsx_sensor_bus_t` endpoint and `nsx_sensor_runtime_t` hooks.
The endpoint owns the I2C address or SPI chip select, bus locking, native errors,
and the synchronous controller operation. The core owns page selection and wire
command bytes. It requires TX capacity of at least 2 bytes and RX capacity of at
least 23 bytes. I2C combined transfers must use repeated START; SPI must hold CS
across command and data. Do not map the current STOP-separated NSX helper to
this contract. The shared NSX adapter is a follow-up dependency.

The application owns power, pinmux, and bus configuration. I2C addresses are
`0x76` or `0x77`; 4-wire SPI supports mode 0 or 3 up to 10 MHz. Keep all users of
a shared SPI controller compatible with its settings unless the adapter restores
per-device settings while holding the bus lock.

Zero-initialize one context per sensor. Bind copies lightweight descriptors;
their ops tables and user bindings must outlive the context. Serialize device
operations and do not rebind a pending conversion. No heap or mutable global
device state is used. Fields beginning with `_` are driver-owned.

`bind` does no I/O. `validate_config` is pure. `probe` reads identity without
resetting the device (SPI may select a page). `init` validates explicit settings,
probes, resets, waits 10 ms, loads calibration, applies settings and disables the
heater. `reset` invalidates state; call `init` again before sampling.

```c
#include <nsx/sensors/bme688.h>

nsx_sensor_status_t setup_environment(bme688_context_t *sensor,
                                      const nsx_sensor_bus_t *bus,
                                      const nsx_sensor_runtime_t *runtime)
{
    bme688_config_t config = bme688_default_config(); /* T2/P16/H1, filter 3 */
    nsx_sensor_status_t status = bme688_bind(sensor, bus, runtime);
    if (status != NSX_SENSOR_OK) return status;
    return bme688_init(sensor, &config);
}
```

Provide a `delay_us` hook that waits at least the requested elapsed interval.
Its user pointer is independent of the bus endpoint. Supply `now_us` for elapsed
polling budgets; otherwise only requested delays count toward timeouts. Retain
the context after initialization and use start/collect or measure repeatedly.

## Sleeping during conversion

`bme688_start` triggers a forced conversion and returns an estimated wait in
microseconds. It performs no conversion delay. The wait uses Bosch's forced-mode
conversion estimate, the **encoded** heater duration, and a 1 ms guard. The
application can return to its scheduler and sleep the MCU while waiting.

```c
uint32_t wait_us;
nsx_sensor_status_t status = bme688_start(&sensor, &wait_us);
if (status != NSX_SENSOR_OK) return status;
/* Schedule collection after wait_us, or sleep for at least wait_us here. */
app_delay_us(timing_user, wait_us);
status = bme688_collect(&sensor, &sample);
/* NSX_SENSOR_AGAIN: schedule another bounded collection attempt. */
```

`bme688_collect` makes one burst read and never delays or retries internally.
It returns `NSX_SENSOR_AGAIN` while conversion is active or when no new data exists.
Start drains the previous field before triggering; collection uses `new_data`
and the measuring flags to identify a fresh completed result. The measurement
index is reported but need not change: datasheet sections 5.3.6.1 and 5.3.6.7
define new-data status and document index advancement for parallel mode only.
Zero, repeated, and wrapped indices are accepted. A successful collection consumes that
pending conversion; a second collection requires another start. An I/O error
leaves the conversion pending so collection can be retried. Starting while one
is pending returns `NSX_SENSOR_E_BUSY`. Call `bme688_sleep` to cancel collection.

`bme688_measure` uses elapsed microseconds after starting when `now_us` is
provided; otherwise its timeout bounds requested delays and excludes transport
latency and scheduler oversleep. `bme688_sleep` uses the same policy. One final
collection/status check is allowed at expiry, but no further wait is issued.
A synchronous HAL call cannot be preempted; the adapter must document its own
finite completion bound. Timeout leaves collection pending; retry collection
or cancel with sleep. Sleep cancels pending collection even on timeout.

Configuration setters request sleep and poll at 1 ms intervals with a 5 s delay
budget before writing settings. The BME688 can ignore mode/control writes until
the current conversion ends, so setters can block for that interval. Use them
between samples. No measurement loop or queue is started by configuration.

## Settings, validity, and failure recovery

`bme688_set_config` / `bme688_get_config` use typed oversampling and IIR settings.
Temperature oversampling must stay enabled: pressure and humidity compensation
require the current temperature. Either P/H channel can be disabled. Its sample
validity flag is then false and numeric result is zero. A completed sample always
has a compensated temperature.

`bme688_set_heater` accepts a target of 0..400 C, duration of 1..4032 ms, and
ambient temperature of -40..85 C when enabled. Invalid inputs cause no register
traffic. Heater duration is quantized **down** by the hardware's exponent/mantissa
encoding; `bme688_get_heater` returns actual duration and resistance codes. The
requested heater target cannot be read back. For example, 100 ms encodes as
`0x59`; 65 ms becomes 64 ms. Disabled heater configuration ignores temperature
and duration inputs, turns off gas, and removes heater time from the estimate.

Check both `sample.gas_valid` and `sample.heater_stable` before using resistance.
They reflect separate sensor status bits; a valid conversion may precede heater
stability. Gas resistance is zero when gas is disabled or the gas-valid bit is
clear. Temperature/pressure/humidity remain available in either case.

Read APIs leave the output unchanged on failure. Shared transport statuses
propagate unchanged; native HAL diagnostics belong to the endpoint binding.
Reset failures propagate and initialization failures require reinitialization.
A partial configuration or heater write invalidates cached settings; retry the
setter or initialize again. A failed read can consume hardware data even when
no sample is published, so retrying cannot guarantee recovery of that sample.

## Portable transport and testing

The core handles SPI page selection and command bits. Each combined read sends
one command byte followed by receive clocks. Each write sends one register/value
pair; ordinary auto-increment register writes are not supported by the part.
Page state is read on access so a failed write cannot poison a software cache.

Run `tests/portable_build.sh` for core tests, sanitizers, independent target
selection, C/C++ header linkage, and nested/relocated installed consumers.
`tests/bme688_host_unit.sh cc` also runs the BME688 suite directly. All fixtures
are synthetic. Fixed compensation vectors come from the unmodified Bosch v4.4.8
public APIs; see `PROVENANCE.md`. No physical hardware has been qualified.
